We&rsquo;ve reinvented Windows Vista&rsquo;s never-ending UAC dialogs, and just like Vista, the only thing it actually trains users to do is click through.</p> <p>The permission model is fundamentally broken. Approving that is fine. The problem is that most of what an agent actually wants to do isn&rsquo;t a clean file edit. It&rsquo;s a multi-step bash invocation chaining <code>find</code> into <code>xargs</code> into <code>sed</code>, or an inline Python script, or a <code>jq</code> pipeline that the UI truncates after the first couple of hundred characters.</p> <p>Reviewing those properly takes real time. Reading a 30-line shell pipeline, working out what each step does, checking that nothing is being deleted that shouldn&rsquo;t be, tracing where stdout is going to end up — that&rsquo;s not a click, that&rsquo;s a code review. And the agent fires off another one twenty seconds later.</p> <p>There are two outcomes. Either you do the careful review every time and spend more time vetting the agent than the agent saves you, or you stop reading and click yes. In practice everyone ends up at &ldquo;click yes&rdquo; within a couple of hours of real use (if that). No prompts, no review of every command — this is the box, do whatever you need inside it.</p> <p><a href="https://github.com/ajsutton/claude-docker">claude-docker</a> is one way to do this — run the agent in a container so the side effects are contained on a layer you can throw away. There are plenty of other options, many/most of them more polished and with much finer-grained controls over what the agent can reach. The built-in sandbox features in agent executors could work just as well too, but they all seem to default to &ldquo;ask permission&rdquo; rather than &ldquo;deny&rdquo;, and the sandbox they create is usually too small to actually get work done. So you end up turning the protections off or whitelisting things case by case, and you&rsquo;re back where you started.</p> <p>The bar to set is: everything the agent has access to should be safe enough that you&rsquo;d happily run it under <code>--dangerously-skip-permissions</code> without a second thought. A hook that searches for <code>git push</code> will miss most of these, and a malicious agent — or a benign agent that has been prompt-injected — will find a route through.</p> <p>Hooks are still useful, just not as security. If you want the agent to be able to push but want a confirmation step on the way out, a hook will catch the common case and that&rsquo;s a perfectly nice workflow as long as you don&rsquo;t mind it failing every now and then.
